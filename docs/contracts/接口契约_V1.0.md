# 可信 RegRAG 接口契约 V1.0

状态：冻结。负责人：陈伦禄。代码实现：`src/regrag/contracts.py`。发布 Schema：`schemas/`。

## 1. QueryPlan

负责把问题变成可执行检索计划，包含 `query_id`、问题类型、槽位、澄清状态、是否多跳、路由和最大跳数。

约束：

- `route_plan` 至少一项；
- `max_hops` 为 1–3；
- 未知字段拒绝；
- 需要澄清时必须在最终 `AnswerResponse` 提供澄清问题。

## 2. EvidenceRecord

所有 Word、PDF、Excel 解析器的唯一公共输出。任何检索器不得绕过 EvidenceStore 直接把原始块拼入 Prompt。

约束：

- `doc_id` 与 SHA-256 格式严格校验；
- 表格证据保留 Sheet、Cell、行/列表头、Header Path、值、单位、期间和脚注；
- `validation_status` 区分 `unreviewed`、`auto_checked`、`verified`、`rejected`；
- 未确认的版本状态保持 `unknown`，不得伪造现行有效。

## 3. AnswerResponse

统一最终状态为 `answered`、`clarify`、`refused`、`conflict`、`error`。

状态不变量：

- `answered` 必须同时有答案、Evidence ID 和 Citation；
- `clarify` 必须有 `clarification_question`；
- `refused` 必须有 `refusal_reason`；
- 引用至少包含 Evidence ID、可读位置和可选原文摘录。

## 4. TraceRecord

记录 Query 解析、检索、重排、证据门控、工具、生成和验证步骤。每一步必须包含输入/输出引用、状态和耗时。

正式评测必须补充总 Token 与成本；未调用 LLM 时填 0，不得留作未知后再宣称低成本。

## 5. BaselineRunResult

代码模型位于 `src/regrag/run_result.py`，统一封装：

- 方法、版本、实现状态、配置哈希、EvidenceStore、评测集和随机种子；
- QueryPlan、Top-K RetrievalHit、AnswerResponse、TraceRecord；
- 延迟、Token 和估算成本。

## 6. 兼容与变更

- V1.0 只允许新增可选字段；
- 删除字段、改变类型或语义必须提升主版本；
- Schema、代码模型、样例和测试必须在同一提交更新；
- Agent 接口冻结不代表完整 Agent 已实现。
