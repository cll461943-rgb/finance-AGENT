# 统一仓库与分支规范 V0.1

## 1. 单一主工程

仓库根目录是唯一运行入口。解析、索引、Baseline、评测和公开输出均通过仓库内相对路径连接，不允许把个人电脑绝对路径写成默认配置。

固定一级目录：`configs/`、`data/`、`index/`、`baselines/`、`evaluation/`、`outputs/`、`schemas/`、`src/`、`tests/`、`docs/`。

## 2. 分支与合并

- `main` 保持可运行。
- 功能分支：`feature/<topic>`；修复分支：`fix/<topic>`；文档分支：`docs/<topic>`。
- 合并前至少通过契约测试、相关功能测试、敏感信息扫描和代码审查。
- 不使用强推覆盖共享历史；需要撤销时用可审计的回滚提交。

## 3. 配置

- 运行参数进入 `configs/`，凭证只从环境变量读取。
- 配置必须记录数据版本、模型版本、Top-K、随机种子和方法开关。
- 方法专有参数可新增，但不得暗改公共预算。

## 4. 日志与结果命名

- 运行 ID：`RUN-<12位十六进制>`。
- Trace ID：`TRACE-<12位十六进制>`。
- 正式结果：`YYYYMMDDTHHMMSSZ__方法__数据版本__配置哈希前8位.json`。
- 禁止提交 `.env`、缓存、模型、索引、受限原始语料和含个人敏感信息的日志。

## 5. 外部代码

外部项目必须在 `THIRD_PARTY_NOTICES.md` 记录来源、版本、许可证、用途和实际改动。不得直接把外部仓库或删去版权信息后的代码作为团队原创成果。

## 6. 最小验收命令

```powershell
$env:PYTHONPATH = "src"
py -3.12 -m pytest -q
py -3.12 -m regrag list-methods
py -3.12 -m regrag validate-evidence --evidence-store <evidence_store.jsonl>
```
