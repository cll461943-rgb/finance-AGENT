# 可信 RegRAG 系统接口说明 V1.0

## 1. 目的

本接口说明用于统一数据解析、检索、证据判别、工具调用、生成与评测模块之间的数据契约。当前版本属于设计冻结稿，不代表端到端系统已经完成。

## 2. 核心对象

### 2.1 QueryPlan

输入用户问题，输出问题类型、关键槽位、澄清状态、多跳状态和计划调用的检索路径。Schema：`schemas/query_plan.schema.json`。

### 2.2 EvidenceRecord

所有解析器必须输出统一 EvidenceRecord。条款、段落和表格单元格不得直接拼接成 Prompt，必须先进入统一证据存储。Schema：`schemas/evidence_record.schema.json`。

关键要求：

- Word/PDF：至少保留文件、页码或字符区间、章节/条款信息；
- Excel：至少保留 Sheet、Cell、行表头、列表头、Header Path、值、单位、期间、脚注；
- 质量状态必须区分自动检查与人工确认；
- 未确认的版本状态不得伪造为现行有效。

### 2.3 AnswerResponse

系统最终输出需要兼容赛题标准答案字段，并增加状态、引用和 Trace。Schema：`schemas/answer_response.schema.json`。

### 2.4 TraceRecord

记录查询解析、检索、重排、证据判别、工具、生成和自核过程。Schema：`schemas/trace_record.schema.json`。

## 3. 模块边界

| 模块 | 输入 | 输出 | 禁止事项 |
|---|---|---|---|
| 文档解析 | 原始文件、Manifest | EvidenceRecord | 不得仅输出无位置的纯文本块 |
| 检索 | QueryPlan、Evidence Store | 候选 EvidenceRecord + 分数 | 不得直接生成最终答案 |
| 重排 | 问题、候选证据 | 排序后的候选证据 | 不得修改原始证据内容 |
| Evidence Gate | 问题、候选证据、版本信息 | sufficient / insufficient / conflicting | 证据不足不得放行生成 |
| 工具层 | 已核验字段、明确操作 | 可复核计算结果 | 不得让 LLM 自由执行未约束代码 |
| 生成层 | 最小充分证据集 | AnswerResponse | 不得使用证据外知识补齐监管结论 |
| 自核层 | 答案、原始证据 | 通过 / 重试 / 拒答 | 关键实体未定位不得通过 |

## 4. 第一版主链

```text
原始文件
→ 统一解析
→ EvidenceRecord
→ BM25 / Dense
→ RRF
→ Metadata Filter
→ Reranker
→ Evidence Gate
→ 受约束生成
→ 数字/日期/机构/文号自核
→ AnswerResponse + TraceRecord
```

## 6. 版本规则

- Schema 变更必须提升 `schema_version`；
- 主分支仅合并通过最小测试的代码；
- 外部开源代码必须记录来源、许可证和改动范围；
- `.pytest_cache`、`__pycache__`、`.ruff_cache`、模型缓存和 API Key 不进入提交包；
- 所有评测结果必须保存数据版本、解析器版本、模型、参数和时间戳。
